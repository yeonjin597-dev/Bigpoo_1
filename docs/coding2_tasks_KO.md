# 코딩 2 작업 지시서

코딩 1이 데이터 파이프라인과 본분석 Cox 모형(`analysis_main.py`)을 완료하였다.
코딩 2의 역할은 **결과 검증, 데이터 기술통계, 결과 그림 전체 작성, 양도 판정 채점**이다.

| 번호 | 작업 | 결과 파일 | 예상 소요 | 마감 |
| --- | --- | --- | --- | --- |
| 1 | 본분석 결과 재현 | 코딩 1에게 메시지 | 30분 (대부분 대기) | 금 (늦어도 토) |
| 2 | 모든 표의 `n`·`events` 확인 | 코딩 1에게 메시지 | 15분 | 금 (늦어도 토) |
| 3 | 발표용 표 | `out/1127_발표표_coding2.xlsx` | 1시간 | 금 (늦어도 토) |
| 4 | 기술통계 노트북 | `notebooks/02_descriptive_coding2.ipynb` | 2~3시간 | 금 (늦어도 토) |

- `data/`, `*.parquet`, `*.pkl`, `sheets/` 안의 파일은 깃허브에 올리지 않는다 (`.gitignore`로 이미 차단되어 있음).

- 결과는 "원인"이 아니라 **"통제 후 남는 연관"**으로 서술한다.

## 작업 4. 기술통계 노트북 (`notebooks/02_descriptive_coding2.ipynb`)
**목적:** 모형 이전 단계에서 **원자료 → 분석 표본 → 단순 패턴**의 연결을 보여 준다. 교수님 평가 기준인 "원자료와의 관계 제시"에 해당한다.

입력 파일: `out/analysis_table_v2.parquet` (1행 = 가게 1곳, 2013~2022년 개업)

주요 열:

| 열 | 의미 |
| --- | --- |
| `prior_closures` | 이 가게 개업 직전 3년 동안 같은 칸(지번+층)에서 발생한 진짜 폐업 수 |
| `prior_closures_cat` | 위 값을 문자로 구분: `'0'`, `'1'`, `'2'`, `'3'`, `'4+'` |
| `duration_days`, `event_ours` | 생존 기간(일), 진짜 폐업 여부 (1 = 폐업, 0 = 영업 중 또는 양도) |
| `dead_3y` | 개업 후 3년 안 진짜 폐업 여부 (1/0) |
| `single_unit_site` | True = 같은 층에 동시에 가게가 하나뿐인 칸 (주분석 표본, 결정 D1) |
| `gu`, `open_year`, `area_rq8`, `category` | 구, 개업 연도, 지역 유형(골목/발달/상권밖/전통시장), 업태 |

구성:
1. **표본 흐름표:** 전체 개업 → `single_unit_site == True` → M4 통제변수 결측 제외. 마지막 숫자는 `표본 요약` 시트를 사용한다.
2. **이전 폐업 횟수별 3년 안 폐업률:** (가) 전체 표, (나) 주표본 각각에 대해 가게 수와 폐업률(%) 표, 막대그래프.
3. **Kaplan–Meier 생존곡선:** 주표본에서 이전 폐업 0 / 1 / 2회 이상 세 집단 (`lifelines.KaplanMeierFitter`).
   가로축 = 개업 후 연수(0~10년), 세로축 = 영업 지속 비율. **log-rank 검정**(`lifelines.statistics.multivariate_logrank_test`)의 p값을 함께 제시한다.
4. **개업 연도별:** `open_year`(2013~2022)별 3년 안 폐업률과 이전 폐업 1회 이상 비율.
   2022년 개업 가게는 관찰 기간이 짧으므로 모든 연도 비교에는 `dead_3y`만 사용한다.
5. **지역 유형별**(`area_rq8`): 가게 수, 이전 폐업 1회 이상 비율, 3년 안 폐업률.
6. **구별**(`gu`): 25개 구에 대해 같은 표를 만들고 3년 안 폐업률 순으로 정렬한다. **상호·주소는 넣지 않는다.**
7. 마지막에 "관찰 결과" 마크다운 셀을 둔다 (3~5개 항목, 숫자 중심, "원인" 표현 금지).

> **확인:**
> - 전체 111,484곳 → 주표본 57,842곳 → 결측 제외 56,224곳 (진짜 폐업 25,229건)
> - 3년 안 폐업률(전체 표): 0회 23.6%, 1회 29.1%, 2회 33.2%, 3회 35.9%, 4회 이상 50.8%
> - 3년 안 폐업률(주표본, 결측 제외): 0회 21.3%, 1회 25.0%, 2회 이상 30.3%
> - `area_rq8` 가게 수(전체 표): 발달상권 45,616 / 골목상권 35,280 / 상권밖 20,145 / 전통시장 9,578 / 결측 865

## 작업 6. 양도 판정 채점 (`score_transfer.py`)
**목적:** 컴퓨터의 양도 규칙이 사람의 판정과 얼마나 일치하는지 측정하여, 규칙을 근거 있게 확정한다.

**시작 조건:** 코딩 1이 파일을 전달한 뒤에 시작한다 (비코딩 2의 판정이 끝난 뒤). 정답 파일은 판정자에게 전달되어서는 안 된다.

배경: 가게가 폐업하고 같은 칸에 새 가게가 들어올 때, 간격이 30일 이하이면 컴퓨터는 **양도**(주인만 바뀌고 영업은 이어짐)로 판정한다.
비코딩 두 명이 표본을 직접 판정하였다. 이 작업은 컴퓨터 규칙이 사람 판정과 일치하는 비율을 계산한다.

실행: `python score_transfer.py <판정파일1.xlsx> [<판정파일2.xlsx>]`

입력:

| 파일 | 시트 / 열 |
| --- | --- |
| 판정 파일 `1124b_양도판정_비코딩N_완료.xlsx` | 시트 `판정`: `구분`(본인/교차), `번호`, `A. 업태(하는 장사) 이어짐`, `B. 상호·간판 이어짐`, `C. 로드뷰`, `최종 판정`, `메모` |
| 정답 파일 `sheets/1124_양도판정385_정답_코딩1만.xlsx` | `번호`, `묶음`(A/B/C), `간격_일`, `코드_판정`(컴퓨터 판정) |

묶음: A = 간격 0~30일 (컴퓨터 판정 = 양도), B = 31~90일, C = 91~365일 (컴퓨터 판정 = 폐업후새가게)
가중치용 모집단 크기: **A 19,806 / B 3,610 / C 5,227**

판정 규칙 (판정자가 규칙대로 판정했는지 확인할 때 다시 적용한다):
```
B == '예'                        → '양도'
B == '아니오' 그리고 A == '아니오'  → '폐업후새가게'
B == '아니오' 그리고 A == '예'     → C == '이어짐'이면 '양도', C == '끊김'이면 '폐업후새가게', 그 외 '판단불가'
그 외                             → '판단불가'
```

결과 파일 `out/1127_양도판정_채점.xlsx`에 다음 시트를 각각 만든다.
1. **묶음별 채점:** `구분 != '교차'`인 줄만 사용하고 `판단불가`는 제외한다. 판정한 줄 수, 판단불가 수, 일치 수, 일치율, **Wilson 95% 신뢰구간**(`statsmodels.stats.proportion.proportion_confint(k, n, method='wilson')`), 사람이 양도로 판정한 비율.
   마지막 줄에 위 모집단 크기로 **가중한 전체 일치율**을 넣는다.
2. **판정자별 규칙 준수:** `최종 판정`이 규칙 재적용 결과와 같은 비율, 로드뷰 이어짐/끊김 건수, 사진없음 건수
3. **규칙과 다른 판정 목록** (확인용)
4. **묶음별 오판정률** = 1 − 일치율 (코딩 1이 오분류 시뮬레이션에 사용)
5. **두 판정자 간 일치도** (파일이 2개일 때만): 한 판정자의 `교차` 25줄과 같은 `번호`를 다른 판정자가 판정한 결과를 비교하여 단순 일치율과 **Cohen κ**를 계산한다. 공식은 직접 구현한다: κ = (p_o − p_e) / (1 − p_e)
6. **추가:** 대안 규칙 "간격 60일 이하 **그리고** B == '예' → 양도"로 같은 채점표를 만든다 (코딩 1이 검토 중인 규칙).

> **확인 (비코딩 1 파일만 넣었을 때):** A 9/50 = 18.0% (신뢰구간 9.8~30.8%), B 51/56 = 91.1%, C 43/45 = 95.6%, 가중 전체 약 41.4%, 규칙 준수율 100% (193/193)
